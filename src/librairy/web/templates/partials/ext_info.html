{# The info control that appears beside a filename, everywhere one is shown. A native popover. No JavaScript: `popovertarget` toggles on click, Escape closes, clicking elsewhere light-dismisses, and it is keyboard-operable and announced for free. The CSP forbids inline script, so a popover library was never an option and is not missed for two sentences of reference text. It used to be a `
`, which was the right instinct and the wrong primitive. A `
` panel is an ordinary absolutely-positioned element, so it lives inside whatever its ancestors do — and this control sits beside a filename, which is the single most clipped place on any page. On Review the filename heading carries a `-webkit-line-clamp`, so that a long name cannot make a row 496px tall. That clamp needs `overflow: hidden`, which clipped this panel out of existence. Measured in a real browser: `details.open === true`, panel laid out at 360x118, heading clip box 24px tall, zero pixels of the panel inside it, and `elementFromPoint` at the panel's centre returning `null`. The control opened perfectly and painted nothing, which is exactly why it was reported as "does nothing" rather than as an error. Browse has the same shape of hazard for a different reason: its rows sit inside a scrolling pane. Chasing each surface would have left the next one to find. A popover renders in the top layer — outside every `overflow`, every clip and every stacking context by construction — so there is no third screen waiting to break.
