One-Way Backup

After each commit, LibrAIry copies newly filed files to a remote you have already configured in rclone, verifies each copy, and stops there. One-way means exactly that: nothing is ever read back, changed, or deleted at either end. It is a safety net against losing this machine, not a sync — edit a file on the remote and LibrAIry will neither notice nor object.

What gets copied

Only files already committed to your library — never the inbox, never quarantine. Sizes are what is there today; the backup grows as you commit more.

LM Studio (local, on your LAN)

Running LM Studio on another machine? Type its IP — http:// and :1234 are filled in for you. No API key, nothing leaves your network.

  1. In LM Studio, open the Developer tab and start the server.
  2. Turn on Serve on Local Network in the same panel. Without it the server only answers its own machine, and LibrAIry will time out.
  3. Load a model, then press Test below to see it listed here.

Test checks the address in the box above — you do not have to save a wrong one to find out it is wrong.

Ollama Endpoints

{# The feature was here all along and nothing said so — the form looked like it configured the local Ollama rather than any machine on the network. #}

Ollama does not have to run on this machine. Add as many as you like — a desktop with a real GPU, a second server, anything on your LAN — and give each one the URL it answers on, like http://192.168.1.50:11434. LibrAIry tries them in the order they appear in the provider order above and falls through to the next when one is down. Nothing leaves your network, and no key is involved.

Ollama only listens to its own machine unless you tell it otherwise: set OLLAMA_HOST=0.0.0.0 on the machine running it, then Test here to confirm this container can reach it.
